RUST

package

  • 包含一个Cargo.toml
  • 有0-1个library crate
  • 包含任意数量的binary crate
  • 至少包含一个crate

代码组织

  • 主要包括：
  • 哪些细节可以暴露，哪些细节是私有的
  • 作用域哪些名称有效
  • package:cargop的特性，让你构建，测试，共享crate
  • crate：模块数，产生宇哥library或者可执行文件
  • module：控制组织，作用域，私有路径
  • path：为struct、function、module命名

crate

  • 将相关的组合到一个作用域内

类型

  • library
  • binary

类型

  • crate root
  • 默认为main.rs(可执行文件)/lib.rs(二进值文件)

moudle

  • 代码分组
  • 增加可读性
  • 控制私有性

建立

  • mod关键字
  • 可嵌套
  • 可包含其他项定义
mod ftan{
    mod sss{
        fn asdasds(){}
    }
    mod sss{
        fn asdasds(){}
    }
}

路径

  • 和其他语言的命名空间比较像
  • 绝对路径
  • 相对路径
  • 也用::去引用

私有边界

  • 默认所有的条目默认私有
pub fn saldk(){}
  • 以上实现了一个公有的模块

super

  • 上级目录使用super模块

use关键字

  • 可以用use将路径引用到当前路径

as

  • 可以将路径重命名

use重新导入作用域

  • pub use去重新导入，外部也可以使用

使用外部包

  • 在cargo.toml里加入
[dependencies]
package_name="package_version"
  • 标准库也会作为外部包，外部条件仍然要引入
  • 使用嵌套路径，可以清理繁琐包引用
use 相同路径::{不同的路径}

*(通配符)

  • 将所有的模块导入

如何拆分 

mod mod_name{}
  • 就可以导入文件了

unity

inspector

  • 选中则显示游戏对象关联的脚本信息
  • 信息下面是脚本（组件）-类
  • 用面向对象的方式去做角色设置

Console

  • 有打印信息才可以快捷打开
