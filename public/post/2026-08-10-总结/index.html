单例的线程安全的

线程安全的方式有：

1. 互斥锁 std::mutex + std::lock_guard

最基础、最常用。保护一段临界区代码，同一时刻只有一个线程能进入。

std::mutex mtx;
std::map<std::string, int> table;
void update(const std::string& key, int val) {
std::lock_guard<std::mutex> lock(mtx);  // RAII，作用域结束自动解锁
table[key] = val;
}
  • lock_guard：构造时加锁，析构时解锁，绝对安全。
  • unique_lock：更灵活，可以手动 lock()/unlock()，也可配合条件变量用。
  • 适用：99% 的场景。临界区短，代码简单。

2. 原子操作 std::atomic<T>

适合计数器、标志位、简单累加等单一变量的操作。无锁，性能远高于 mutex。

std::atomic<int> counter{0};
void worker() {
for (int i = 0; i < 1000; ++i)
counter.fetch_add(1);  // 原子自增
}

注意：std::atomic 只保证单个变量的操作是原子的。如果涉及多个变量的“先检查后操作”，还是得用锁。

3. 条件变量 std::condition_variable

用于线程间等待/通知。经典的生产者-消费者模型就用它。

std::mutex mtx;
std::condition_variable cv;
std::queue<int> tasks;
void producer() {
{
std::lock_guard<std::mutex> lock(mtx);
tasks.push(42);
}
cv.notify_one();  // 唤醒一个等待线程
}
void consumer() {
std::unique_lock<std::mutex> lock(mtx);
cv.wait(lock, []{ return !tasks.empty(); });  // 防止虚假唤醒，加条件判断
int t = tasks.front();
tasks.pop();
}

关键是：wait 会原子地释放锁并挂起线程，被唤醒后重新拿锁。

4. 读写锁 std::shared_mutex（C++17）

读多写少的场景下，允许多个线程同时读，但写独占。

std::shared_mutex rw_mtx;
std::map<std::string, int> cache;
int read(const std::string& k) {
std::shared_lock<std::shared_mutex> lock(rw_mtx);  // 共享锁，可多个读
return cache[k];
}
void write(const std::string& k, int v) {
std::unique_lock<std::shared_mutex> lock(rw_mtx);  // 独占锁，写时阻塞所有读
cache[k] = v;
}

5. 线程局部存储 thread_local

每个线程有自己独立的副本，天然无竞争，无需加锁。

thread_local int t_counter = 0;  // 每个线程各一份
void func() {
t_counter++;  // 无需锁，各线程互不影响
}

6. 无锁队列/无锁容器

高性能场景下用。官方没有标准实现，推荐第三方库：

  • concurrentqueue（moodycamel）：单生产者单消费者/多生产者多消费者都很快。
  • boost.lockfree: boost::lockfree::queue<T>、boost::lockfree::stack<T>，适合 SPSC/MPMC 场景。 这些只能在简单数据结构、明确内存序下用，否则容易出难以排查的 bug。

7. 避免共享的设计（最优雅的方案）

  • 消息传递模型：线程间不共享数据，只通过队列传递消息（配合 mutex + condition_variable 实现）。
  • 线程池 + 任务队列：每个任务发给空闲线程，数据独占即可。
  • 你自己写的 businessPool、TaskQueue 就是这个思路——生产者把任务塞进队列，消费者（工作线程）各取各的。

对比总结

方式 场景 性能 复杂度
mutex 通用临界区 中 低
atomic 单一变量计数/标志 高 低
condition_variable 等待/通知 中 中
shared_mutex 读多写少 中高 中
thread_local 每线程独立副本 极高 极低
lockfree 高频消息队列 高 高
消息传递/避免共享 架构设计层面 最好 需要设计

Grid 与响应式设计

Grid 概述

  • CSS Grid（网格布局）是二维布局系统，同时控制行和列
  • 与 Flexbox（一维、适合单行/单列）互补：Flexbox 管"一排/一列"，Grid 管"整张表"
  • 由**容器（container）和项目（item）**组成，通过 display: grid 启用
.container {
  display: grid; /* 块级网格 */
  /* display: inline-grid;  行内网格 */
}

Grid 容器属性

1. 定义轨道：grid-template-columns / grid-template-rows

  • 用空格分隔的多个长度值，每个值代表一条轨道（列/行）
  • 常用单位：px、%、fr（剩余空间分配）、auto、repeat()、minmax()
.container {
  grid-template-columns: 100px 200px 1fr; /* 固定 + 自适应 */
  grid-template-rows: 80px 1fr; /* 头部 + 剩余占满 */
}

repeat() 简化重复轨道 

.container {
  /* 3 列等分 */
  grid-template-columns: repeat(3, 1fr);
  /* 等价于: 1fr 1fr 1fr */
}

minmax(min, max) 弹性区间 

.container {
  /* 每列至少 200px，最多等分剩余空间 */
  grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));
}
  • auto-fill：自动填充尽可能多的列（大于 200px 就多放几列，实现响应式卡片布局）

2. 间距：gap（简写 row-gap + column-gap） 

.container {
  gap: 20px 30px; /* 行间距 20px，列间距 30px */
}

3. 区域的合并写法：grid-template-areas

用命名区域把格子拼成布局，配合项目的 grid-area 使用

.container {
  grid-template-columns: 200px 1fr;
  grid-template-rows: 80px 1fr 60px;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
}

4. 对齐：容器内所有项目的整体对齐

属性 作用 常见值
justify-content 所有网格整块在容器内水平对齐（轨道没占满时） start / center / end / space-between / space-around
align-content 所有网格整块垂直对齐 同上
justify-items 每个项目在格子内水平对齐 stretch(默认) / start / center / end
align-items 每个项目在格子内垂直对齐 同上 
.container {
  justify-content: center;
  align-content: start;
  justify-items: stretch;
  align-items: center;
}

5. 自动轨道与流动：grid-auto-rows / grid-auto-columns / grid-auto-flow

  • 项目数量超出显式定义的行列时，用 grid-auto-* 兜底
.container {
  grid-auto-rows: minmax(100px, auto); /* 隐式行高兜底 */
  grid-auto-flow: row; /* 默认：按行排列，满了换行 */
  /* grid-auto-flow: column;  按列排列 */
  /* grid-auto-flow: dense;   密集排列，尽量不留空洞 */
}

Grid 项目属性

1. 定位：grid-column / grid-row（线编号从 1 开始） 

.item {
  grid-column: 1 / 3; /* 从第 1 条线到第 3 条线（占 2 列） */
  grid-row: 1 / 2; /* 占 1 行 */
}

简写常用法：

.item {
  grid-column: 1 / -1; /* -1 代表最后一条线：一行占满 */
  grid-row: 2 / span 2; /* 从第 2 行开始，跨越 2 行 */
  grid-column: span 3; /* 跨 3 列（从当前自动位置开始） */
}

2. 命名区域：grid-area 

.header {
  grid-area: header;
}
.sidebar {
  grid-area: sidebar;
}
.main {
  grid-area: main;
}
.footer {
  grid-area: footer;
}

也可以一行写完四条线（row-start / column-start / row-end / column-end）：

.item {
  grid-area: 1 / 1 / 3 / 3;
}

3. 项目自身对齐：justify-self / align-self / place-self

覆盖容器上的 justify-items / align-items

.item {
  justify-self: center; /* 自己在格子内水平居中 */
  align-self: end; /* 垂直靠底 */
  place-self: center; /* 简写：水平垂直都居中 */
}

4. order 排序

与 flex 一样，改变项目在网格中的显示顺序（默认 0，越小越靠前）。

经典 Grid 布局示例：后台管理页面 

.layout {
  display: grid;
  height: 100vh;
  grid-template-columns: 200px 1fr;
  grid-template-rows: 60px 1fr 50px;
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
}
.layout .header {
  grid-area: header;
}
.layout .sidebar {
  grid-area: sidebar;
}
.layout .main {
  grid-area: main;
}
.layout .footer {
  grid-area: footer;
}

<div class="layout">
  <div class="header">顶部导航</div>
  <div class="sidebar">侧边栏</div>
  <div class="main">主内容区</div>
  <div class="footer">页脚</div>
</div>

媒体查询 + viewport + rem 移动端适配

1. viewport 视口设置

移动端适配的前提：不写 viewport，手机上页面会按 PC 宽度缩小显示。

<meta
  name="viewport"
  content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no"
/>
参数 含义
width=device-width 布局视口 = 设备宽度
initial-scale=1.0 初始缩放比例 1:1
maximum-scale=1.0, user-scalable=no 禁止用户手动缩放（一般由产品决定是否开启）

2. 媒体查询 @media

根据屏幕宽度（或其他媒体特性）应用不同样式，是响应式的核心手段。

/* 默认：手机优先（min-width 从小到大写） */
.container {
  grid-template-columns: 1fr; /* 手机：单列 */
}

/* ≥ 768px：平板 */
@media (min-width: 768px) {
  .container {
    grid-template-columns: repeat(2, 1fr);
  }
}

/* ≥ 1024px：桌面 */
@media (min-width: 1024px) {
  .container {
    grid-template-columns: repeat(4, 1fr);
  }
}

其他常用写法：

@media (max-width: 767px) {
  /* 小于等于 767px */
}
@media (min-width: 768px) and (max-width: 1023px) {
  /* 区间 */
}
@media (orientation: landscape) {
  /* 横屏 */
}
@media (prefers-color-scheme: dark) {
  /* 深色模式 */
}

常见断点（Breakpoints）

设备 宽度
手机竖屏 < 600px
手机横屏 / 小平板 600px ~ 900px
平板 / 小笔记本 900px ~ 1200px
桌面 > 1200px

3. rem 移动端适配

  • rem 是相对于根元素 <html> 的 font-size 的单位（em 相对于父元素）
  • 思路：用 JS 按屏幕宽度动态设置根字号，页面所有尺寸都用 rem，实现等比缩放
html {
  font-size: 16px; /* 基准：1rem = 16px */
}
.box {
  width: 10rem; /* = 160px */
  padding: 0.5rem; /* = 8px */
}

经典动态设置（配合 flexible.js 思想） 

(function flexible() {
  function setRem() {
    var width = document.documentElement.clientWidth;
    /* 设计稿宽 750，1rem = width / 10 */
    document.documentElement.style.fontSize = width / 10 + "px";
  }
  setRem();
  window.addEventListener("resize", setRem);
})();

效果：设计稿上的 75px → 写 75/75 = 1rem（如果以 750 设计稿、width/10 为基准，则 1rem = 75px，直接除以 75 即可换算）。

注意：rem 方案要配合 <meta name="viewport"> 使用；另一种替代方案是 vw/vh 单位（1vw = 视口宽度的 1%），更简单但兼容性处理稍麻烦。

4. 三种方案的选择

方案 原理 适用
@media 查询 不同宽度不同样式 布局结构不同（移动端导航栏变汉堡菜单等）
rem 根字号等比缩放 图片、字号、间距等按比例缩放
vw/vh 视口单位直接换算 全屏/近全屏页面，配合 flex/grid 使用
Grid auto-fill + minmax 网格自动增减列 卡片流式布局，无需额外媒体查询

CSS过渡与动画

transition 过渡属性

  • 定义元素从一种样式变到另一种样式时的平滑过渡效果
  • 需要触发条件（hover、class 切换等）才能生效
  • 只有可插值的属性才能过渡（如 width、color、opacity、transform 等）

四个子属性

属性 作用 示例值
transition-property 指定要过渡的属性 all（默认）、opacity、transform, background-color
transition-duration 过渡持续时间 0.3s、200ms
transition-timing-function 速度曲线 ease（默认）/ linear / ease-in / ease-out / ease-in-out / cubic-bezier(...)
transition-delay 延迟开始时间 0s（默认）、0.5s 
.box {
  width: 100px;
  background: #42b983;
  /* transition: 属性 时长 速度曲线 延迟 */
  transition: all 0.3s ease 0s;
}
.box:hover {
  width: 200px;
  background: #35495e;
}

简写 & 多属性分开写 

/* 简写：所有属性 0.3s */
transition: all 0.3s;

/* 多个属性用逗号分隔，可分别设置时长 */
transition:
  transform 0.4s ease,
  opacity 0.2s linear 0.1s;

/* 分开写（等价的完整形式） */
transition-property: transform, opacity;
transition-duration: 0.4s, 0.2s;
transition-delay: 0s, 0.1s;

注意：display: none ↔ block 无法过渡（渲染树直接重建），可以用 opacity + visibility 或 max-height 模拟。

transform 变换

transform 只是视觉变形，不影响文档流，也不改变其他元素的布局位置。

2D 变换函数

函数 作用 示例
translateX / translateY / translate 平移（px、%、translate(-50%, -50%) 常用于水平垂直居中） transform: translate(20px, 30px)
rotate(deg) 旋转（正值顺时针） transform: rotate(45deg)
scale(x, y) 缩放（1 为原大小） transform: scale(1.2)
skew(deg) 斜切/倾斜 transform: skew(10deg, 5deg) 
.box {
  transition: transform 0.3s;
}
.box:hover {
  transform: translateY(-5px) scale(1.05) rotate(2deg); /* 多个变换空格分隔，从右往左应用 */
}

变换原点 transform-origin

默认以元素中心为原点（50% 50%），可改为左上角、底部等。

.box {
  transform-origin: left top; /* 以左上角为轴旋转 */
  transform-origin: 0 100%; /* 左下角 */
  transform: rotate(30deg);
}

3D 变换（配合 perspective）

  • perspective：视距，给父容器设置才有立体感
  • rotateX / rotateY / rotateZ：绕轴旋转
  • translateZ：沿 Z 轴移动（景深）
.scene {
  perspective: 800px; /* 视距：数值越小 3D 效果越强 */
}
.card {
  transform: rotateY(60deg); /* 绕 Y 轴翻转 */
  transform-style: preserve-3d; /* 让子元素保持 3D 空间 */
}

常用技巧：transform: translate(-50%, -50%) + absolute 定位，完成不关心元素宽高的水平垂直居中。

animation 关键帧动画

@keyframes 定义

用关键帧描述动画过程，无需触发条件，加载后自动播放。

@keyframes 动画名 {
  from {
    opacity: 0;
    transform: translateY(20px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

/* 或用百分比控制中间帧 */
@keyframes loading {
  0% {
    transform: scale(1);
  }
  50% {
    transform: scale(1.5);
  }
  100% {
    transform: scale(1);
  }
}

animation 子属性

属性 作用 示例值
animation-name 引用 @keyframes 的名字 loading
animation-duration 一个周期时长 1s、500ms
animation-timing-function 速度曲线 ease / linear / steps(4)
animation-delay 延迟启动 0s、0.5s（负值相当于直接跳到中间状态）
animation-iteration-count 播放次数 1、infinite（无限）
animation-direction 方向 normal / reverse / alternate（交替双向）
animation-fill-mode 播放前后状态 none / forwards（保持结束状态）/ backwards（延迟期间应用首帧）/ both
animation-play-state 播放/暂停 running / paused 
.loading {
  animation: loading 1s ease-in-out infinite;
}

/* 长格式写法 */
.ball {
  animation-name: loading;
  animation-duration: 1s;
  animation-timing-function: linear;
  animation-iteration-count: infinite;
  animation-direction: alternate;
  animation-fill-mode: both;
}

/* 鼠标悬停暂停 */
.loading:hover {
  animation-play-state: paused;
}

简写顺序 

animation: name duration timing-function delay iteration-count direction
  fill-mode;
/*             ↓        ↓          ↓       ↓             ↓          ↓        ↓        */
animation: loading 1s ease 0s infinite alternate both;

/* 多动画逗号分隔 */
animation:
  loading 1s infinite,
  fadeIn 0.5s ease;

transition vs animation 对比

对比项 transition 过渡 animation 动画
触发方式 需要触发性事件（hover、class 切换） 自动播放，无需触发
关键帧控制 只有起点和终点两态 支持多关键帧（0% ~ 100%）
循环播放 不支持 支持 infinite
控制播放次数/方向/暂停 不支持 支持次数、方向、play-state
适合场景 按钮 hover、菜单展开、颜色切换 loading 动画、入场动画、持续循环动效

组合示例：hover 放大 + 阴影 + 持续呼吸 

.btn {
  transition:
    transform 0.3s,
    box-shadow 0.3s; /* 用过渡做交互动效 */
}
.btn:hover {
  transform: scale(1.05);
  box-shadow: 0 8px 20px rgba(0, 0, 0, 0.2);
}

  100% {
    transform: scale(1);
  }
  50% {
    transform: scale(1.08);
  }
}
.badge {
  animation: breath 2s ease-in-out infinite;
}
