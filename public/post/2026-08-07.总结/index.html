计算长方形面积

最简单的 

fn main() {
   let w=30;
   let l=200;
   println!("{}",w*l);
}

使用函数 

fn main() {
   let w=30;
   let l=200;
   println!("{}",area(w, l));
}

fn area(width:u32,length:u32) -> u32 {
   width*length
}

函数+元组 

fn main() {
   let rect=(30,50);
   println!("{}",area(rect));
}

fn area(dim:(u32,u32)) -> u32 {
   dim.0*dim.1
}

函数+结构体 

struct Recttangle{
   width:u32,
   length:u32
}

fn main() {
   let rect=&Recttangle { width:30,length:50};
   println!("{}",area(rect));
}

fn area(rect:&Recttangle) -> u32 {
   rect.width*rect.length
}
  • 此时函数只是借用了所有权，结束后所有权仍然在main
  • 直接打印rect
  • 不会默认disaply和Debug
#[derive(Debug)]
struct Recttangle{
   width:u32,
   length:u32

fn main() {
   let rect=&Recttangle { width:30,length:50};
   println!("{}",area(rect));
   println!("{:?}",rect)
}

fn area(rect:&Recttangle) -> u32 {
   rect.width*rect.length

bool Connection::connect(std::string ip, unsigned short port, std::string username, std::string password, std::string dbname)
{

	return p != nullptr;

CSS 定位与 Flex 布局

position

五个值

static（默认）
  • 按正常文档流排列，无法用 top/left 等偏移。
  • z-index 不生效——因为 static 元素不参与层叠排序逻辑（相当于永远排在定位元素之下）。
relative
  • 保留原空间（不脱离文档流），通过 top/right/bottom/left 相对自身原本位置偏移。
  • 偏移后可能覆盖其他元素，此时 z-index 可调整层级。
.box {
  position: relative;
  top: 10px;      /* 相对原位置向下偏移 10px */
  left: 20px;
  z-index: 5;     /* 生效 */
}
absolute
  • 完全脱离文档流，不再占据空间。
  • 定位参照是最近的已定位祖先（position ≠ static）。
.parent {
  position: relative; /* 关键：作为参照 */
}
.child {
  position: absolute;
  top: 0;           /* 相对 .parent 左上角 */
  z-index: 10;
}
  • 若祖先都没有定位，则相对初始包含块（通常是浏览器视口，且会随页面滚动而移动，注意与 fixed 的区别）。
fixed
  • 脱离文档流，始终相对视口定位，页面滚动时不会跟着滚动。
  • 常用于：导航栏、返回顶部按钮、悬浮弹窗。
.nav {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  z-index: 1000;
}
  • 陷阱：如果祖先有 transform / perspective / filter 等属性，会创建新的包含块，fixed 会变为相对该祖先定位。
sticky（粘性定位）
  • 是 relative 与 fixed 的结合体：
  • 未滚动到阈值时 → 像 relative，在文档流中占据位置；
  • 滚动到阈值后 → 像 fixed，黏在滚动容器内。
.header {
  position: sticky;
  top: 0;          /* 滚动到顶距 0 时开始黏住 */
  z-index: 100;
}
  • 常见用途：表头吸顶、分类菜单吸顶。
  • 注意：sticky 的滚动容器必须是最近的可滚动祖先；若祖先设置 overflow: hidden/auto 会限制其黏住范围。

z-index

1. 只对「定位元素」生效

  • 只有 position: relative / absolute / fixed / sticky 时该属性才有意义。

2. 数值含义

  • auto（默认）:不参与层叠上下文创建，按文档顺序和定位类型排序
  • 0:与 auto 类似，但会创建层叠上下文
  • 正整数:数值越大，层级越高，显示越靠前
  • 负整数（如 -1）:可以低于普通（static）内容，甚至可以跑到父元素背景之下
.box-a { position: relative; z-index: 1; }
.box-b { position: relative; z-index: 999; }
/* box-b 覆盖 box-a */

.box-c { position: relative; z-index: -1; }
/* box-c 会跑到父元素背景层下面 */

3. 相同 z-index 时 → 看 DOM 顺序

  • 如果层级相同，后面的元素覆盖前面的元素
<div class="box" style="position:relative; z-index:1; background:red;">A</div>
<div class="box" style="position:relative; z-index:1; background:blue; margin-left:50px;">B</div>
<!-- B 覆盖 A 的交叉部分 -->

4. 层叠上下文（Stacking Context）

  • z-index 的比较只在同一个层叠上下文内有效。多种情况会创建层叠上下文：
  • position:定位 + z-index != auto
  • opacity < 1
  • transform / perspective / filter / backdrop-filter 非 none
  • mix-blend-mode 非 normal
  • display: flex / grid 的子元素且 z-index != auto
  • position: fixed / sticky（总是创建）
  • contain: paint / layout、will-change 指定上述属性等
  • 核心原则：子元素的 z-index 只在父级层叠上下文中比较，无法跨越父级 与外部元素比较。
/* 父级 context-a 的 z-index=1 */
.context-a { position: relative; z-index: 1; }
  .inner-a { position: relative; z-index: 999; }

/* 父级 context-b 的 z-index=2 */
.context-b { position: relative; z-index: 2; }
  .inner-b { position: relative; z-index: 1; }

/* 结果：即使 inner-a 有 999，整个 context-a 仍被 context-b 覆盖 */

Flex 容器属性

display: flex 与主轴/交叉轴

  • 设置 display: flex 后，元素变为 flex 容器，直接子元素自动成为 flex item。
  • 主轴（main axis）：由 flex-direction 决定；
  • 交叉轴（cross axis）：与主轴垂直。
  • justify-content 控制主轴对齐，align-items / align-content 控制交叉轴对齐。

flex-direction（主轴方向） 

.container {
  display: flex;
  flex-direction: row;            /* 默认：水平，从左到右 */
  /* row-reverse | column | column-reverse */
}
  • row（默认）：主轴水平从左到右
  • row-reverse：水平从右到左
  • column：垂直从上到下
  • column-reverse：垂直从下到上

flex-wrap（换行） 

.container {
  flex-wrap: nowrap;   /* 默认：不换行，可能溢出 */
  /* wrap | wrap-reverse */
}
  • nowrap（默认）：不换行
  • wrap：换行，多行排列
  • wrap-reverse：换行且反向排列

flex-flow（简写） 

.container {
  flex-flow: row wrap;   /* flex-direction + flex-wrap */
}

justify-content（主轴对齐） 

.container {
  justify-content: flex-start;   /* 默认 */
  /* flex-end | center | space-between | space-around | space-evenly */
}
  • flex-start（默认）：起点对齐
  • flex-end：终点对齐
  • center：居中
  • space-between：两端对齐，项目之间间距相等
  • space-around：每个项目两侧间距相等
  • space-evenly：项目之间与容器边缘间距完全相等

align-items（交叉轴对齐，单行） 

.container {
  align-items: stretch;   /* 默认 */
  /* flex-start | flex-end | center | baseline */
}
  • stretch（默认）：拉伸填满容器
  • flex-start：交叉轴起点
  • flex-end：交叉轴终点
  • center：交叉轴居中
  • baseline：文字基线对齐

align-content（交叉轴对齐，多行） 

.container {
  align-content: stretch;   /* 默认 */
  /* flex-start | flex-end | center | space-between | space-around */
}
  • 仅当有多行（flex-wrap: wrap 生效）时有意义
  • stretch：拉伸填满
  • flex-start / flex-end / center：整体对齐
  • space-between / space-around：行间分布

gap（间距） 

.container {
  gap: 12px;          /* 行间距和列间距都是 12px */
  row-gap: 8px;       /* 行间距 */
  column-gap: 16px;   /* 列间距 */
}

Flex 项目属性

order（排列顺序） 

.item {
  order: 0;   /* 默认 0，数值越小越靠前 */
}
  • 默认所有项目 order 为 0，按 DOM 顺序排列
  • 可以设为负数让项目排在最前

flex-grow（放大比例） 

.item {
  flex-grow: 0;   /* 默认：不放大 */
}
  • 默认 0，空间有剩余时也不放大
  • 数值越大，分到的剩余空间越多
  • 多个项目都为 1 时，平分剩余空间

flex-shrink（缩小比例） 

.item {
  flex-shrink: 1;   /* 默认：可缩小 */
}
  • 默认 1，空间不足时等比例缩小
  • 设为 0：空间不足时也不缩小（容易溢出）

flex-basis（主轴初始大小） 

.item {
  flex-basis: auto;   /* 默认：按内容或 width/height */
}
  • 可以用 px / % / 关键字
  • 优先级高于 width/height

flex（简写） 

.item {
  flex: 1;         /* 相当于 1 1 0% */
  flex: auto;      /* 相当于 1 1 auto */
  flex: none;      /* 相当于 0 0 auto */
}
  • 语法：flex: <flex-grow> <flex-shrink> <flex-basis>

align-self（单独对齐） 

.item {
  align-self: auto;   /* 默认：继承父容器 align-items */
  /* flex-start | flex-end | center | baseline | stretch */
}
  • 覆盖父容器的 align-items，只对当前项目生效

常见陷阱

  • 子元素的 margin: auto 在 flex 布局中会吸收剩余空间，可用来快速居中
  • flex 容器属性（justify-content / align-items）不作用于 flex 容器本身，只作用于它的直接子元素
  • 如果项目没有设置 flex-basis，默认按内容大小计算；设置了 flex-grow 后才会填充剩余空间
